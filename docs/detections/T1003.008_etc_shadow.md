# T1003.008 — /etc/shadow read or copied

| | |
|---|---|
| **ATT&CK** | [T1003.008](https://attack.mitre.org/techniques/T1003/008/) |
| **Tactic** | Credential Access |
| **Severity** | high |
| **Engine** | Falco → `Read sensitive file untrusted` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects a process reading or copying /etc/shadow — offline credential dumping.

## Detection logic

```yaml
selection:
  Image|endswith:
  - /cat
  - /cp
  - /head
  - /tail
  - /less
  - /more
  - /xxd
  - /base64
  CommandLine|contains: /etc/shadow
condition: selection
```

Falco (eBPF, host syscalls) raises **`Read sensitive file untrusted`** from a Falco stock rule. Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1003.008`

*Read /etc/passwd and /etc/shadow for offline cracking*

```bash
cat /etc/passwd > /tmp/dll_passwd ; cat /etc/shadow > /tmp/dll_shadow 2>/dev/null || true ;
rm -f /tmp/dll_passwd /tmp/dll_shadow
```

`./lab verify T1003.008` then asserts the alert reached the indexer.

## Known false positives

- Backup jobs, security scanners (rare, usually allowlisted)
