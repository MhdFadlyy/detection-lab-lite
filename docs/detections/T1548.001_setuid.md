# T1548.001 — Setuid/setgid bit set via chmod

| | |
|---|---|
| **ATT&CK** | [T1548.001](https://attack.mitre.org/techniques/T1548/001/) |
| **Tactic** | Privilege Escalation |
| **Severity** | high |
| **Engine** | Falco → `DLL Setuid Bit Set` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects chmod adding the setuid/setgid bit to a file — a common privilege-escalation persistence trick.

## Detection logic

```yaml
selection:
  Image|endswith: /chmod
  CommandLine|contains:
  - +s
  - u+s
  - g+s
  - ' 4755'
  - ' 6755'
  - ' 2755'
condition: selection
```

Falco (eBPF, host syscalls) raises **`DLL Setuid Bit Set`** from the custom rule in [`detections/falco/dll_rules.yaml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/falco/dll_rules.yaml). Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1548.001`

*Set the setuid bit on a dropped binary (privilege-escalation persistence)*

```bash
cp /bin/dash /tmp/dll_suid 2>/dev/null || cp /bin/sh /tmp/dll_suid
chmod u+s /tmp/dll_suid
ls -l /tmp/dll_suid ; rm -f /tmp/dll_suid
```

`./lab verify T1548.001` then asserts the alert reached the indexer.

## Known false positives

- Package post-install scripts setting setuid on legitimate binaries
