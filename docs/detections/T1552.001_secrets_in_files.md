# T1552.001 — Filesystem grep for secrets

| | |
|---|---|
| **ATT&CK** | [T1552.001](https://attack.mitre.org/techniques/T1552/001/) |
| **Tactic** | Credential Access |
| **Severity** | medium |
| **Engine** | Falco → `DLL Credential Search` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects recursive grep for password/token/secret patterns — searching the filesystem for unsecured credentials.

## Detection logic

```yaml
selection:
  Image|endswith:
  - /grep
  - /egrep
  - /rg
  CommandLine|contains:
  - password
  - passwd
  - secret
  - api_key
  - token
condition: selection
```

Falco (eBPF, host syscalls) raises **`DLL Credential Search`** from the custom rule in [`detections/falco/dll_rules.yaml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/falco/dll_rules.yaml). Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1552.001`

*Recursively grep /etc and /home for credential strings*

```bash
grep -rniE 'password|api_key|secret|token' /etc /root 2>/dev/null | head -n 5 || true
```

`./lab verify T1552.001` then asserts the alert reached the indexer.

## Known false positives

- Developers searching their own code
