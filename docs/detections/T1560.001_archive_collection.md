# T1560.001 — Archive of a sensitive path via tar/zip

| | |
|---|---|
| **ATT&CK** | [T1560.001](https://attack.mitre.org/techniques/T1560/001/) |
| **Tactic** | Collection |
| **Severity** | medium |
| **Engine** | Falco → `DLL Archive Collection` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects tar/zip/gzip archiving a sensitive-looking path (/etc, /root, /home), a common way to stage data before exfiltration.

## Detection logic

```yaml
selection:
  Image|endswith:
  - /tar
  - /zip
  - /gzip
  CommandLine|contains:
  - /etc
  - /root
  - /home
condition: selection
```

Falco (eBPF, host syscalls) raises **`DLL Archive Collection`** from the custom rule in [`detections/falco/dll_rules.yaml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/falco/dll_rules.yaml). Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1560.001`

*Archive a sensitive path with tar before staging it for exfil*

```bash
tar czf /tmp/dll_loot.tar.gz /etc/passwd /root/.ssh 2>/dev/null
rm -f /tmp/dll_loot.tar.gz
```

`./lab verify T1560.001` then asserts the alert reached the indexer.

## Known false positives

- Legitimate backup jobs archiving those same paths
