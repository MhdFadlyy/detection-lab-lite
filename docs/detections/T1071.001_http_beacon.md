# T1071.001 — Cleartext HTTP beacon marker on the wire

| | |
|---|---|
| **ATT&CK** | [T1071.001](https://attack.mitre.org/techniques/T1071/001/) |
| **Tactic** | Command And Control |
| **Severity** | medium |
| **Engine** | Wazuh (Suricata) → rule `100610` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects a distinctive marker string in cleartext TCP traffic, standing in for a C2 beacon or exfil string an attacker sends over a plain HTTP-shaped request. Custom Suricata signature, not a stock/ET Open rule, so it's self-contained and doesn't depend on a rule feed download.

## Detection logic

```yaml
selection:
  alert.signature: DLL HTTP Beacon Marker
condition: selection
```

Suricata (network IDS, sharing `target-linux`'s network namespace) matches a custom signature in [`compose/suricata/dll.rules`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/compose/suricata/dll.rules) and writes EVE JSON to a shared volume; the `target-linux` agent tails it, and rule `100610` in [`0600-suricata.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0600-suricata.xml) matches on `alert.signature`.

## Attack scenario — `./lab attack T1071.001`

*Send a distinctive cleartext HTTP-shaped request carrying a beacon marker*

```bash
curl -s --max-time 3 "http://cowrie:2222/DLL_BEACON_MARKER" || true
```

`./lab verify T1071.001` then asserts the alert reached the indexer.

## Known false positives

- None expected — the marker string is unique to this lab's scenario
