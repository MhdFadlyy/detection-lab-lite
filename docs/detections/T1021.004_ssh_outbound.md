# T1021.004 — Outbound SSH client execution

| | |
|---|---|
| **ATT&CK** | [T1021.004](https://attack.mitre.org/techniques/T1021/004/) |
| **Tactic** | Lateral Movement |
| **Severity** | low |
| **Engine** | Falco → `DLL Outbound SSH` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects execution of the ssh/sshpass client from a server workload — possible lateral movement.

## Detection logic

```yaml
selection:
  Image|endswith:
  - /ssh
  - /sshpass
condition: selection
```

Falco (eBPF, host syscalls) raises **`DLL Outbound SSH`** from the custom rule in [`detections/falco/dll_rules.yaml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/falco/dll_rules.yaml). Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1021.004`

*Attempt an outbound SSH connection (fails fast, still executes the client)*

```bash
timeout 5 ssh -o StrictHostKeyChecking=no -o ConnectTimeout=2 -o BatchMode=yes dll@127.0.0.1 id || true
```

`./lab verify T1021.004` then asserts the alert reached the indexer.

## Known false positives

- Admin jump-host workflows, CI deploy steps, git-over-ssh
