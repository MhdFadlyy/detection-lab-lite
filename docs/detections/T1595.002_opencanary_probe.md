# T1595.002 — Interaction with the OpenCanary decoy service

| | |
|---|---|
| **ATT&CK** | [T1595.002](https://attack.mitre.org/techniques/T1595/002/) |
| **Tactic** | Reconnaissance |
| **Severity** | medium |
| **Engine** | Wazuh (Opencanary) → rule `100710` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects any interaction with the OpenCanary honeypot (FTP/HTTP decoy services). Nothing legitimate ever talks to a honeypot, so every logged event here is by definition a probe or vulnerability scan.

## Detection logic

```yaml
selection:
  node_id|exists: true
condition: selection
```

OpenCanary (FTP/HTTP decoy services) logs the interaction as JSON to a shared volume; the `target-linux` agent tails it, and rule `100710` in [`0700-opencanary.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0700-opencanary.xml) fires on any event, nothing legitimate ever talks to a honeypot.

## Attack scenario — `./lab attack T1595.002`

*Probe the OpenCanary decoy FTP and HTTP services*

```bash
timeout 3 curl -s http://opencanary/ >/dev/null 2>&1 || true
timeout 3 nc -z opencanary 21 2>&1 || true
```

`./lab verify T1595.002` then asserts the alert reached the indexer.

## Known false positives

- None expected — this honeypot has no legitimate users
