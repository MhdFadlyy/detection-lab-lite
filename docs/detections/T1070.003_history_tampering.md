# T1070.003 — Shell history file truncated or deleted

| | |
|---|---|
| **ATT&CK** | [T1070.003](https://attack.mitre.org/techniques/T1070/003/) |
| **Tactic** | Defense Evasion |
| **Severity** | medium |
| **Engine** | Falco → `DLL Shell History Tampering` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects removal or truncation of a shell history file (or `history -c`) — an attacker covering their tracks.

## Detection logic

```yaml
selection_file:
  Image|endswith:
  - /rm
  - /unlink
  - /truncate
  - /shred
  CommandLine|contains: history
selection_builtin:
  Image|endswith:
  - /bash
  - /sh
  - /zsh
  CommandLine|contains: history -c
condition: selection_file or selection_builtin
```

Falco (eBPF, host syscalls) raises **`DLL Shell History Tampering`** from the custom rule in [`detections/falco/dll_rules.yaml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/falco/dll_rules.yaml). Falco writes its JSON events to a shared volume; the `target-linux` Wazuh agent tails that file, so the alert lands in the Wazuh indexer as a `1009xx` rule ([`0900-falco.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0900-falco.xml)), matched on `data.rule`.

## Attack scenario — `./lab attack T1070.003`

*Truncate the bash history file to cover tracks*

```bash
touch /root/.bash_history
truncate -s 0 /root/.bash_history
ls -l /root/.bash_history
```

`./lab verify T1070.003` then asserts the alert reached the indexer.

## Known false positives

- User housekeeping (rare on servers)
