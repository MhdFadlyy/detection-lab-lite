# T1098.004 — SSH authorized_keys modified

| | |
|---|---|
| **ATT&CK** | [T1098.004](https://attack.mitre.org/techniques/T1098/004/) |
| **Tactic** | Persistence, Lateral Movement |
| **Severity** | high |
| **Engine** | Wazuh FIM → rule `100312` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects writes to an authorized_keys file — attacker adding an SSH key for persistent access.

## Detection logic

```yaml
selection:
  TargetFilename|endswith: authorized_keys
condition: selection
```

Wazuh FIM (`syscheck`, inotify real-time) fires **rule `100312`** from [`detections/wazuh-native/0300-persistence.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0300-persistence.xml) (`<if_group>syscheck</if_group>` + a `file` regex).

## Attack scenario — `./lab attack T1098.004`

*Append an attacker SSH key to root's authorized_keys (persistence — not reverted; ./lab down clears it)*

```bash
mkdir -p /root/.ssh
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIdllTESTKEYdllTESTKEYdllTESTKEY attacker@evil" >> /root/.ssh/authorized_keys
tail -n1 /root/.ssh/authorized_keys
```

`./lab verify T1098.004` then asserts the alert reached the indexer.

## Known false positives

- Legitimate key rotation by configuration management or the user
