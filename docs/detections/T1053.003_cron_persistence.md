# T1053.003 — Crontab modified via CLI

| | |
|---|---|
| **ATT&CK** | [T1053.003](https://attack.mitre.org/techniques/T1053/003/) |
| **Tactic** | Persistence |
| **Severity** | medium |
| **Engine** | Wazuh FIM → rule `100310` |
| **Automated test** | ✅ attack replayed + alert asserted in CI |

## What it detects

Detects use of the crontab binary to install a scheduled task — a common persistence mechanism.

## Detection logic

```yaml
selection:
  Image|endswith: /crontab
condition: selection
```

Wazuh FIM (`syscheck`, inotify real-time) fires **rule `100310`** from [`detections/wazuh-native/0300-persistence.xml`](https://github.com/MhdFadlyy/detection-lab-lite/blob/main/detections/wazuh-native/0300-persistence.xml) (`<if_group>syscheck</if_group>` + a `file` regex).

## Attack scenario — `./lab attack T1053.003`

*Install a cron job via crontab (persistence — not reverted; ./lab down clears it)*

```bash
(crontab -l 2>/dev/null; echo "* * * * * /usr/bin/id > /tmp/dll_cron") | crontab -
crontab -l
```

`./lab verify T1053.003` then asserts the alert reached the indexer.

## Known false positives

- Configuration management (Ansible, Puppet) installing legitimate jobs
